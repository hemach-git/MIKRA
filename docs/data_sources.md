Equipment names (Press Line 2, CNC-04, Conveyor C3, …), people, extensions (ext. 5555) and specifications are fictional. **Do not use them as real procedures.**

## Model register

| Role | Model | Status |
|---|---|---|
| Fallback pipeline and tests | `mock-extractive-v1` (deterministic, no AI) | Built, used by tests and evals today |
| Router, specialists, synthesizer agents | `gpt-4o-mini` via the OpenAI API (set in `config.yaml`, key in `.env`) | **Built.** Live smoke call and 9-question smoke run OK; formal eval pending |
| Alternative provider | Anthropic Claude: v1 classifier and answer path only. **The agent chat adapter is not implemented**; adding it is a small change to `llm.chat` | Not validated |

- **Config of record:** `config.yaml`. Its hash is stored on each `ask` audit row and in each eval result (`config_snapshot`). v2 adds the prompt version and the agent mode.
- **Secrets:** `.env` only (gitignored). `.env.example` has placeholders.

## Data handling with a live LLM

- In agent mode, the **PII-masked question and the retrieved document sections are sent to the LLM provider's API.**
- This prototype contains only synthetic data, so no real plant information leaves the machine.
- Before any real documents are used, review the provider's data-retention terms and get internal approval.
